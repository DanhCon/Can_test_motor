3. Driver ZLAC Modbus cũ (đã đọc source)

  • zlac8015d_driver/src/zlac8015d_driver.cpp — API Modbus: enable(0x08)/disable(0x07)/eStop(0x05)/clearAlarm(0x06) qua 0x200E; mode 0x200D (1 rel / 2 abs / 3 vel); setRPM clamp ±max_rpm; getRPM/10; pos 0x20A7 4 regs; volt *0.01; temp driver *0.1.
  • zlac8015d_driver/src/zlac_interfaces.cpp — node zlac_driver_node: sub /nhatbot/wheel_rotational_vel Float32MultiArray (rad/s) → RPM → setRPM(-left, right); pub /nhatbot/JointState 10 Hz (đang comment); service reset encoder.
  • nhatbot_firmware/src/nhatbot_hw_interface.cpp — NhatbotInterface : SystemInterface: export position+velocity state / velocity command; read() pos rad + vel rad/s; write() rad/s → RPM.
  • nhatbot_firmware/include/.../driver_manager.hpp — singleton + mutex; init() = enable + SPEED_RPM + accel 100 / decel 100.
  • nhatbot_firmware/src/zlac_sdk.cpp — bản SDK đầy đủ: retry 3 lần, autoReconnect, setRPM(left, -right), tick (Left, -Right).
  • Params: modbus_port /dev/zlac_8015d, 115200, accel/decel 1000 ms, max_rpm 200, cpr 4096, R 0.0535. Nhược điểm: blocking ~10 Hz, hay rớt, PC dí trực tiếp driver.
Kết luận: bỏ toàn bộ cụm Modbus + ros2_control khi sang hệ mới (hướng 2). Không giữ code Modbus nào.

4. IMU BNO055 (đã đọc kỹ source)

4.1 Cấu trúc driver (gốc flynneva/bno055)

  • bno055/bno055.py — node bno055, 2 timer read_data + calib có threading.Lock chống đè.
  • bno055/sensor/SensorService.py — configure() check chip ID 0xA0 → CONFIG → PWR_NORMAL → UNIT_SEL 0x83 → axis remap → offsets → mode 0x0C NDOF. get_sensor_data() burst 45 bytes từ 0x08, normalize quaternion tay. get_calib_status() JSON sys/gyro/accel/mag 0–3. Service calibration_request.
  • Cấu hình đang chạy (params/bno055_params_i2c.yaml): i2c bus 1, addr 0x28, 100 Hz, calib 0.1 Hz, frame imu_link, P0, acc×100/mag×16M/gyr×900/grav×100, set_offsets=true (offsets của xe cũ).
  • Topics: bno055/imu, /imu_raw, /mag, /grav, /temp, /calib_status. TF tĩnh launch: base_link → imu_link [0.175, -0.048, 0.041].

4.2 Nối trực tiếp vào TX2 có đảm bảo không?

Được, đủ dùng cho AMR tốc độ thấp nếu làm đúng: dây <20 cm, xoắn SDA/SCL/GND, tránh bó dây motor, trở kéo 2.2k–4.7k, bắt đệm cao su xa nam châm, cấp đúng 3.3V I2C.
  • Hạ 100 → 50 Hz cho đồng nhịp vòng UDP 50 Hz (driver Python hay warn skipping query cycle trên 30 Hz).
  • Verify: i2cdetect 10 lần đều thấy 28; ros2 topic hz /bno055/imu ổn định; calib tới 3,3,3,3; chạy tải 5 phút không rớt.
  • Bắt buộc calib lại — offsets trong yaml là của xe khác. Tắt set_offsets lần đầu, calib tay, gọi service lấy số mới ghi đè.

4.3 Các bước làm IMU (chi tiết)

  1. Đấu I2C (mặc định, không nối PS1), COM3=GND → 0x28.
  2. sudo apt install i2c-tools && sudo i2cdetect -y -r 1 phải thấy 28 (Jetson bus có thể không phải số 1).
  3. Copy package sang workspace mới, pip install pyserial==3.4, colcon build --packages-select bno055. Đổi frame_id: imu_link, hạ 50 Hz.
  4. Đo lại vị trí gắn → sửa static TF + P0–P7 (sai là yaw lệch 90/180°).
  5. Calib lại từ đầu, lưu offsets mới, bật set_offsets lại.
  6. Fuse EKF (robot_localization): odom0=/odom + imu0=/bno055/imu, two_d_mode=true.

5. LiDAR + mạng Ethernet (TX2 chỉ 1 cổng)

Không dùng cục chia RJ45 1→2 thụ động (không nguồn): nó chỉ cho dùng 1 trong 2, hạ 100 Mbps half-duplex, cắm STM32 + LiDAR cùng lúc là rớt cả 2.
Mua switch Ethernet 5 cổng Gigabit có nguồn (loại 5V cho robot) ~200–300k. Sơ đồ: TX2 192.168.1.50 + STM32 192.168.1.100:8888 + LiDAR OLE 192.168.1.x cùng cắm vào switch, cùng subnet /24. Gói UDP của bạn chỉ 12/22 B × 50 Hz, LiDAR vài Mbps — switch gánh nhẹ.
  • Đặt IP tĩnh cùng dải, test ping cả 2 đều <1 ms.
  • OLE LiDAR (oleros2, dùng libpcap) chạy Ethernet → bắt buộc qua switch. RPLidar chạy USB thì cắm trực tiếp, không ảnh hưởng.
  • Phương án B (không thích switch): USB-to-Ethernet dongle làm NIC thứ 2 — phải chia 2 subnet + route, rắc rối hơn.

7. Toàn repo EIU-FABLAB-AMR (mục 10.6)

Repo cũ là full-stack AMR + tay máy (~19 packages); xe mới hiện mới có tầng chân đế. Đáng bê nhất là tầng Nav2/SLAM/localization + description + safety:

  • GIỮ nhatbot_description (URDF — đo lại xe mới), nhatbot_localization (EKF), nhatbot_mapping / nhatbot_navigation / nav2 (SLAM online_async, Nav2, nav_to_pose, rviz), nhatbot_safety, nhatbot_twist_teleop, differential_drive, behavior/controller/utils, nhatbot_msgs, stack/scripts/maps/rviz.
  • BỎ chân đế Modbus + viết lại nhatbot_bringup.launch.py / build_map.launch.py (đang gọi bringup cũ).
  • ĐỂ SAU nhatbot_dobot_magician, vision_perception (khi xe mới có tay máy/camera), nhatbot_ros2_basic.

8. Kế hoạch chuyển giao (chưa code)

  1. Phần cứng mạng: switch + IP tĩnh 3 bên, ping thông.
  2. IMU: đấu I2C → bus check → build → TF/remap → calib → EKF với /odom.
  3. LiDAR qua switch, fix ole2dv2.yaml, remap /scan + filters.
  4. Port Nav2/SLAM/description/safety sang, sửa TF + limits + trigger lỗi mới.
  5. Calib odom thực tế (multiplier), test teleop → mapping → Nav2.

Thứ tự khi code: diff_drive yaml (TF + limit) → nhatbot_status (pin/lỗi) → filters frame → calib odom.
